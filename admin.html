          Operations guide
          
DiamondRank admin workflow

        

        
      

      

        
Source activation and model publication are separate. Import changes become current only after validation + activation. Rankings change only after the appropriate scoped refresh completes and publication QA passes.


        

          
Routine source update

          

            
1Check freshness & choose source
Review Source freshness, then select the matching import. Hitters and Pitchers have separate Player Masters; supported sources can be exported, edited, and re-imported.

            
2Preview & validate
Upload to staging, review the row-count/change preview, then review validation. Large source-size changes are flagged before activation.

            
3Activate
Activate only after validation passes. The previously current source remains in place until this step succeeds.

            
4Use the recommended scope
Activation preselects the model and refresh scope. Confirm the recommendation before starting.

            
5Run the refresh
Use Run recommended workflow after activation for normal operation, or start manually and use Run to completion. Stages remain resumable if the connection stops.

            
6Confirm Publication PASS
Finish only when the Publication PASS card confirms live public/private hash parity, ranks, rows, contract, and churn.

          

        


        

          
Which refresh scope?

          

            
Formula onlyFORMULA_ONLY
Use after changing weights, score formulas, calibration, or ranking logic while the underlying evidence is unchanged. Reuses existing comps, development, context, and historical caches.

            
Scouting onlySCOUTING_ONLY
Use when scouting evidence changed but statistical source data did not. Both hitter and pitcher Board imports use this path.

            
Data refreshDATA
Use after routine MiLB or MLB statistical updates. Runs the validated evidence, feature, comparable, scoring, and publication workflow.

            
Full rebuildFULL
Use for player-population changes, historical donor-source changes, or major model/data maintenance that can affect the entire dependency chain.

          

        


        

          
Source → refresh map

          

            
Hitters — Player MasterHittersFULL
Export/edit/re-import or direct compatible master import. Updates hitter identities only; omitted existing hitters are preserved.

            
Pitchers — Player MasterPitchersFULL
Export current/relevant pitcher identities, edit/add pitchers, then re-import. Historical donor identities omitted from the file are preserved.

            
Hitters — MiLB stats + SwStrHittersDATA
Routine hitter evidence update.

            
Hitters — MLB seasonsHittersDATA
Routine MLB hitter season-by-season evidence update.

            
Hitters — MLB career totalsHittersDATA
Export/edit/re-import the current career source or upload a fresh FanGraphs career table. Updates current MLB career totals and archives the source snapshot.

            
Pitchers — MiLB current seasonsPitchersDATA
Routine current MiLB pitcher evidence update.

            
Pitchers — MLB seasonsPitchersDATA
Routine MLB pitcher season update.

            
Pitchers — MLB career totalsPitchersDATA
Export/edit/re-import the current versioned career source or upload a fresh FanGraphs career table.

            
Hitters — FanGraphs Board scoutingHittersSCOUTING ONLY
Export/edit/re-import or upload a compatible Board table directly; all rows must resolve to the Hitter Player Master.

            
Pitchers — FanGraphs Board scoutingPitchersSCOUTING ONLY
Scouting changes without a statistical evidence rebuild.

            
Pitchers — historical MiLBPitchersFULL
Historical donor evidence can change, so rebuild the complete validated chain.

          

        


        

          
If a refresh stops or fails

          

            
1Check status
Do not start a second run. Load the existing run first to see the last completed stage.

            
2RUNNING
Resume with Run next stage or Run to completion. The workflow is designed to continue from its saved stage.

            
3FAILED
Review the error, correct the underlying issue, then use Retry failed stage. Do not bypass validation or publication gates.

          

          
The public leaderboard is capped at up to 500 eligible players. The private ranked population is discovered dynamically on each run and is not hard-coded.
